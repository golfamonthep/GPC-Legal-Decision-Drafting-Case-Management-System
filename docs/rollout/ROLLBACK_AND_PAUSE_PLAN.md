# แผนการหยุดพักและถอยกลับ (Rollback and Pause Plan)

## เมื่อใดที่ควรหยุดพักการขยายผล (When to pause rollout)
- พบข้อบกพร่องระดับ S1 (Critical) ที่ส่งผลกระทบต่อผู้ใช้งานจำนวนมาก
- ตรวจพบว่าข้อมูลคดีนำเข้าผิดพลาดและส่งผลต่อผู้ใช้หลายราย
- ระบบทำงานช้าจนไม่สามารถปฏิบัติงานได้ (Performance Degradation)
- มีข้อกังวลด้านความปลอดภัยที่อาจเกิดขึ้น แต่ยังไม่ยืนยันว่าเกิดความเสียหาย

## เมื่อใดที่ควรถอยกลับ (When to rollback deployment)
- เกิดข้อผิดพลาดระดับ S0 (Emergency) เช่น ข้อมูลรั่วไหล หรือข้อมูลสูญหาย
- พบความขัดข้องร้ายแรงหลังจากการนำขึ้นระบบ (Deployment Failure) ที่ไม่สามารถแก้ไขได้อย่างรวดเร็ว

## เมื่อใดที่ควรปิดใช้งาน AI ชั่วคราว (When to disable AI tools temporarily)
- ตรวจพบว่า AI สร้างข้อมูลที่ไม่เหมาะสม ข้อมูลเท็จ (Hallucination) รุนแรง หรือนำความลับไปเปิดเผย
- การใช้ปริมาณ API เกินโควตาที่กำหนด

## เมื่อใดที่ควรปิดระบบการนำเข้าข้อมูล (When to disable registry import temporarily)
- ไฟล์ Excel ต้นฉบับมีปัญหาด้านรูปแบบ (Format change) ทำให้ระบบแปลงข้อมูลผิดพลาดซ้ำๆ

## เมื่อใดที่ควรปิดใช้งานบัญชีผู้ใช้ (When to disable user account)
- ตรวจพบพฤติกรรมน่าสงสัย การละเมิดนโยบายความปลอดภัย หรือการดึงข้อมูลออกโดยไม่ได้รับอนุญาต

## วิธีการถอยกลับเวอร์ชันด้วย Vercel (How to use Vercel rollback)
1. ผู้ดูแลระบบเข้าสู่หน้า Vercel Dashboard
2. ไปที่ Project > Deployments
3. เลือก Deployment ก่อนหน้าที่เสถียร (Stable)
4. คลิก `Promote to Production` หรือ `Revert`
5. รอจนกระทั่งระบบขึ้นสถานะ Ready

## วิธีการเก็บรักษาข้อมูลเพื่อตรวจสอบ (How to preserve data for investigation)
- ไม่ทำการลบหรือแก้ไขฐานข้อมูลในขณะเกิดเหตุ
- ทำการ Export ฐานข้อมูลและ Audit log ล่าสุดทันทีเพื่อเป็นหลักฐาน

## ขั้นตอนการสื่อสารระหว่างการถอยกลับ (Communication steps during rollback)
1. ส่ง **Incident Notice** ให้ผู้ใช้งานทราบถึงการปิดระบบชั่วคราว
2. แจ้งความคืบหน้าทุกๆ 1 ชั่วโมง
3. แจ้งผู้ใช้เมื่อระบบกลับมาใช้งานได้ในเวอร์ชันที่เสถียร

## การทบทวนหลังเกิดเหตุ (Post-incident review)
- เมื่อปัญหาคลี่คลาย ให้จัดทำรายงานสรุปสาเหตุ (Root Cause Analysis) และแผนป้องกัน (Preventive Action) เสนอต่อคณะกรรมการ

# ระบบวิเคราะห์และร่างคำวินิจฉัย

หน้าเริ่มต้นเป็นแดชบอร์ดที่ `/` แสดงจำนวนงานวิเคราะห์ เอกสารรอตรวจข้อความ ฉบับร่างที่บันทึก และงานล่าสุดจากฐานในเครื่อง มีหน้าแยก `/analysis` สำหรับรายการงานและการทำงานวิเคราะห์ กด “สร้างงานวิเคราะห์” เพื่อเริ่ม หรือเปิดงานเดิมผ่าน `/analysis?job=...` ซึ่งรีโหลดได้ เมนู/ปุ่มย้อนกลับรองรับ History API และป้องกันข้อความยังไม่บันทึก ถ้าฐานอ่านไม่ได้ หน้าโฮมแสดงข้อผิดพลาด ไม่แสดงศูนย์แทนข้อมูลที่หายไป

ทางเข้า “เปิดทะเบียนสำนวน” ชี้ทะเบียนเดิมในเครื่องที่พอร์ต 3000 ตัวทะเบียนยังต้องมี Supabase/config ที่ใช้งานได้ก่อนเปิดจริง ข้อมูลแดชบอร์ดวิเคราะห์ไม่ใช่จำนวนคดีในทะเบียน เมนูทะเบียนเพิ่มทางเข้าส่วนวิเคราะห์ที่พอร์ต 4318 โดยไม่ส่งข้อมูลสำนวนเอง

แอปในเครื่องสำหรับรับข้อมูลเฉพาะงาน ตรวจหลักฐาน ค้นฐานอ้างอิงปัจจุบัน แก้ร่างเป็นรายส่วน และส่งออก Word จากฉบับที่เลือก ฐานและไฟล์อยู่ใน `analysis-app/.state` แยกจากทะเบียนผู้ร้องและระบบกรรมการ ไม่มีการอ่านหรือเขียนตาราง Case หรือฐาน production เดิม

เปิด `Start-Analysis.cmd` แล้วเข้า http://127.0.0.1:4318 หากเปิดอยู่แล้ว script จะใช้เซิร์ฟเวอร์เดิม โปรแกรมทำงานเฉพาะ loopback ของเครื่องนี้ ไม่ใช่ระบบหลายผู้ใช้หรือระบบพร้อมเปิดผ่านอินเทอร์เน็ต

## วิธีใช้งาน

เพิ่มทางเชื่อมกับระบบเจ้าของสำนวนแล้ว: ที่หน้าสำนวนเดิมเลือกข้อมูล/เอกสารแล้วส่งเข้าหน้า “รับงานจากสำนวน” ตรวจและยืนยันก่อนรับ งานที่รับจะผูกกับรหัสชุดและเลขสำนวนเดิม ส่งกลับจากฉบับร่างที่เลือก แล้วให้ผู้รับผิดชอบตรวจและยืนยันแนบ Word/รายงานในทะเบียน ใช้ชุด JSON แทนหน้าต่างที่ปิดได้ อ่าน `../docs/ANALYSIS-BRIDGE-SETUP-TH.md` ก่อนตั้งค่าจริง ขณะนี้ฐาน/Storage ของทะเบียนในเครื่องยังไม่เชื่อมสำเร็จ และยังไม่ได้ทดสอบแนบกลับ Supabase จริง

1. กรอกข้อมูลเฉพาะงานแล้วบันทึก เลขอ้างอิงภายนอกเป็นข้อความอ้างอิง ไม่เชื่อมทะเบียน
2. เพิ่มเอกสารในแท็บเอกสาร เปิดต้นฉบับและตรวจข้อความที่ถอดได้ ภาพ/สแกนที่อ่านไม่ได้ต้องถอดหรือแก้ข้อความเอง การรับไฟล์ไม่เท่ากับยืนยันข้อเท็จจริง
3. ค้นฐานอ้างอิง เปิด PDF หน้าอ้างอิง ตรวจชื่อ ตัวเลข ข้อ/มาตรา และข้อความ แล้วอนุมัติแหล่งให้งาน ตัวอย่างคำวินิจฉัยใช้โครงและภาษาเท่านั้น
4. ในผลวิเคราะห์ แยกข้อกล่าวอ้าง ข้อเท็จจริงที่มีหลักฐาน และข้อมูลที่ยังไม่ยืนยัน หากบุคคลไม่มีใน 181 ราย ใช้แบบตรวจภาพบัญชีครั้งที่ 4 เพิ่มอาวุโสเฉพาะงาน จำนวนผู้เหมาะสมใช้ค่าบัญชีที่ตรวจแล้ว ห้ามถือว่าการไม่พบชื่อเป็นการไม่มีชื่อในบัญชี
5. ตำแหน่งว่างจริงต้องมีเอกสารของงานที่ตรวจแล้วและข้อความหลักเกณฑ์ที่ยืนยันว่า 50% ใช้กับกรณีนี้ จึงคำนวณ CEILING(จำนวนตำแหน่งว่างจริง × 0.50) ไม่ใช้จำนวนแต่งตั้งแทน
6. แก้ร่างและบันทึกฉบับใหม่ ข้อเสนอ AI แสดงแยก การขอข้อเสนอใหม่ไม่ทับข้อความมนุษย์ แต่ละส่วนต้องตรวจอ้างอิงก่อนรับข้อความ
7. เลือกฉบับในแท็บส่งออก ดูข้อความ preview แล้วสร้าง/ดาวน์โหลด Word เป็นร่างเบื้องต้น แก้ไฟล์ Word ต่อได้ แต่การแก้ภายนอกไม่ซิงก์กลับ

## ข้อมูลและข้อจำกัดที่สำคัญ

- ตรวจ hash ทั้ง 27 ไฟล์ SQLite และ fingerprint ก่อนเริ่ม หากไม่ตรงจะหยุดรับฐาน ชุดต้นทางเปิด read-only
- การแต่งตั้ง 281 รายเป็นข้อมูล inherited ที่ต้องตรวจต้นฉบับเมื่อใช้อ้าง อาวุโสตรวจภาพ 181 รายไม่ใช่ทั้งบัญชี กฎหมายมีข้อผิดจาก text layer ต้องตรวจย่อหน้าที่ใช้จริง
- รองรับเอกสารไม่เกิน 20 MB, PDF 200 หน้า ข้อความรวม 160,000 อักขระ Excel 5,000 แถวต่อชีต หากตัดข้อความจะแจ้งให้ตรวจครบจากต้นฉบับ ไม่ใช่ OCR อัตโนมัติทุกไฟล์
- AI ใช้ Harness กลางแบบ provider-neutral ค่าเริ่มต้น DeepSeek Responses API, `store:false`, JSON Schema, ไม่มีเครื่องมือค้นเว็บ/คดีอื่น/ฐานทะเบียน และไม่มี fallback อัตโนมัติ ระบบปกปิดชื่อ เลขสำนวน และข้อมูลระบุตัวทั่วไปก่อนส่ง ตรวจรหัสอ้างอิงด้วยโค้ด แต่ความหมายทางกฎหมายต้องตรวจโดยมนุษย์
- เก็บ `AI_API_KEY` และตัวแปร `AI_*` ใน `.env.local` ฝั่ง server เท่านั้น และเปิดด้วย `AI_ENABLED=true` หลัง smoke test ข้อมูลสังเคราะห์ผ่าน ส่วนรับข้อมูล แก้ร่าง และส่งออกทำงานได้โดยไม่มี key; `OPENAI_API_KEY` ไม่ใช่ key สำหรับข้อเสนอของ Harness
- สำรองทั้ง `.state` ขณะหยุดเซิร์ฟเวอร์ รวม SQLite ไฟล์แนบ และ Word ไม่ย้ายเฉพาะไฟล์ฐานตัวเดียวขณะมี WAL ทำงาน ข้อมูลทดสอบแยกจากฐานจริง
- แม่แบบ Word รุ่น analysis-draft-v1 เป็นแม่แบบร่างของระบบนี้ ยังไม่มีแม่แบบทางราชการที่ผู้รับผิดชอบรับรอง ข้อความต้องผ่านผู้รับผิดชอบก่อนใช้

## พัฒนาและตรวจ

React + Vite ส่วนหน้า, Node 24 HTTP/SQLite ส่วนหลัง, Python จาก Codex runtime สำหรับอ่าน PDF/Word/Excel และสร้าง DOCX โฟลเดอร์นี้ไม่ใช้ Next.js ของระบบทะเบียน

`npm run build`, `npm test`, `npm run dev`; integration test ใช้พอร์ต 4319 และฐาน `.qa/state` เท่านั้น อ่าน `QA-REPORT.md` สำหรับหลักฐานและข้อจำกัดการทดสอบ
